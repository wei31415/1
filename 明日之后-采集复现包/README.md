# 明日之后 · 内存读取采集复现包

MuMu 模拟器 + 《明日之后》（`com.netease.mrzh`）安卓端，**纯内存读取**（不靠图像识别）实现的
"走到白名单坐标 → 对准资源 → F×2 + 左键×6" 自动采集工作流。

本包是**可复现快照**：脚本、坐标白名单、示例运行日志、以及全部实测得到的内存结构参数。

## 二、硬性前提（缺一条就跑不起来）

1. **Windows + MuMu 模拟器**已在运行，游戏已进入世界（不是登录界面）。
2. **adb**：`D:/Program Files/Netease/MuMu/nx_main/adb.exe`，设备名 `emulator-5554`。
3. **adb root 必须开启**（读 `/proc/<pid>/mem` 需要 root）。**每次模拟器重启后都要重做一次**：
   ```
   & "D:\Program Files\Netease\MuMu\nx_main\adb.exe" -s emulator-5554 root
   ```

6. 游戏窗口要有焦点 —— 脚本不抢焦点，焦点由使用者自己保证。

## 四、完整工作流（三步）

先把 `scripts` 和 `data` 按第二节放到位，之后**每一步都在 `D:\workspace2\mrzh-tools` 下执行**。

### 第 0 步：定位（每次重启游戏 / 换图 / 读不到相机时做一次）

```powershell
node camfind6.js
```

**按 `docs/相机与玩家定位-实测定稿.md` 的配方执行**，官方包与 vivo 渠道包都验证通过：

1. 背靠背两次转储（dump → 按住 W 800ms → dump，中间不碰鼠标）；
2. 把同 id 节点的位移按 1 单位取整分组，取**数量最多的一簇** → 该位移方向即相机方位角 θ
   （玩家位移在内存里有上百份副本，用"位移最大的单节点"会挑到垃圾）；
3. 扫场景区域全部 4 字节对齐偏移，要求：三行正交归一 + `base+48` 是 `w=1.0` 的位置 +
   某行水平投影方位角与 θ 相差 <3° + 位置距位移簇中心 5~300 单位；
4. **位移复核**：B 转储同偏移的位置位移必须等于该簇位移（实测差 0.00）——这一步决定成败；
5. 通过才写 `session.json`：`yaw = atan2(r2.x, r2.z)`、`pitch = asin(r2.y)`，
   **不需要 ±180、不需要灵敏度常数**。

耗时约 10 秒（三次整区转储）。**会让人物真的走一步**，属正常行为。

> 旧的 `mrzh_locate.js` 用的是"节点配对法"（相机节点＝200000 无限盒）。这条在官方包能用，
> 但 vivo 渠道包里有 40 多个无限盒节点，判据失效。留作参考，新环境请用 `camfind6.js`。

### 第 1 步：记录坐标白名单

游戏里走到资源跟前，**把准心压在资源上**（石头/树/矿都行，准心距 1~5 米最合适），然后：

```powershell
node wl_record.js stone     # type 自己起名：stone / tree / hemp ...
```

脚本做的事：整区转储 → 解析所有 `0e0122`/`0e0022` 节点 → 从相机沿视线发射射线，
与每个节点的 **OBB（位置 + 3×3 旋转 + 模型包围盒）求交** → 取最近且不是玩家/天空盒的那一个 →
把它的**世界坐标（3 位小数）**写进 `whitelist_spawns.json`。

输出示例：

```
相机 (2045.83, 454.73, -4696.39)  yaw 59.6  pitch -36.9
玩家节点 0xc23b   节点总数 592
--- 准心命中列表 ---
  0. 3.28m  0xf25d  指纹 47.94/24.54/36.38  @(2077.090, 416.360, -4676.120)
✓ 已记录 #10：stone (2077.09, 416.36, -4676.12)
```

**射线没命中就不写盘**（会明确打印"准心没命中任何候选物体"），不会写脏数据。
同一坐标 3 米内重复记录只会更新指纹和时间，不会产生重复条目。

### 第 2 步：白名单巡回采集

```powershell
node wlrun2.js --type stone           # 只跑 type=stone 的点
node wlrun2.js                        # 跑全部点
node wlrun2.js --only 3               # 只跑按距离排序后的第 3 个
node wlrun2.js --type stone --loop    # 跑完再来一轮
```

每个点依次执行：

1. **寻路**（`navTo`）：鼠标把视角转到目标方向（误差 >4° 只转身不走）→ 按死 W + 每步点一次跳跃。
   **卡住判定用坐标**：按着 W 但相机坐标在 0.85 秒内位移 < 0.4 米 → 判卡，四级脱困：
   ①侧跳 ②原地连跳+顶 ③后退一步再顶 ④转 40° 绕行；连续 4 次无效才放弃这个点。
2. **到点后重试读 3 次**（每次隔 1.2 秒）：场景节点是流式加载的，刚到点模型可能还没进内存。
3. **按坐标找节点**：只认白名单坐标 3 米内的场景节点，取最近的。**没有节点就跳过，不空挥。**
4. **站位**：算"玩家节点 → 目标包围盒表面距离"，要落在 0.6~2.0 米。
5. **射线咬死**：按包围盒中心算 yaw/pitch，鼠标转过去收敛到 0.25°，然后做射线-OBB 求交，
   要求命中目标且**命中距离 ≤ 4.0 米**。
6. **没进 4 米不许放弃**：朝目标推 300 ms 再重瞄，最多调 8 次位置。
7. **采集**：短按 W 110 ms（让角色朝向跟相机一致）→ `F` ×2（间隔 400 ms）→
   **每按一次左键之前都重新咬住一次目标**，共 6 轮（间隔 1000 ms）。日志会打印每次咬住的距离：
   ```
   左键 1/6（咬住 3.14m）
   左键 5/6（未咬住）        ← 抖开了会明确显示
   ```
   > 为什么每轮都重咬：采集过程中准心会自己抖开（游戏动作/后坐），一次咬死连点 6 下，
   > 后面几下往往已经压在空处。加了重咬之后实测 7 个点里 5 个全程保持 0.9~3.7 米的咬住距离。
   > 代价：每点采集从约 6 秒变成约 25~30 秒（`aimLock` 一次要两次整区转储）。
8. 写 `lastAt / lastResult` 回白名单，下一个点。

### 辅助命令

## 五、核心内存结构（复现的关键，全部为实测）

### 5.1 场景节点

```
marker 位置            0e 01 22 00 00 00        （另有一族 0e 00 22，结构相同）
base = marker 偏移 − 32

marker + 6   u32   节点 id（会复用，不可作为长期身份）
marker + 32  f32×4 位置 (x, y, z, w=1.0)
base   + 88  f32×9 3×3 旋转矩阵，行主序，每行后补 1 个 float
                    行 = 局部轴在世界里的方向；实测正交归一（点积 < 0.001）
base  + 340  f32×3 包围盒 max (x, y, z)
base  + 352  f32×3 包围盒 min (x, y, z)
base  + 364  f32×3 半尺寸 + 0
```

**包围盒就是模型 `.mesh` 里的 local AABB，原样存放，没有旋转、没有缩放。**
核对方式：节点 `0x7fd4` 的 `+340 = 18.063, 15.975, 13.505`、`+352 = -18.063, -1.724, -13.505`，
与 `.mesh` 解包出的模型 `0C3BE6A9D2FC3BDC` 的 max/min **逐位相同**。

### 5.2 相机

```
相机矩阵（session.json 里的 camera_matrix_off）：
  +0   right   (3 f32)
  +16  up      (3 f32)
  +32  forward (3 f32)
  +48  position(4 f32, w=1.0)

yaw   = atan2(fwd.x, fwd.z) * 180 / π      （单位：度）
pitch = asin(fwd.y)          * 180 / π     （正 = 抬头；游戏钳位约 +45° / −60°）
```

### 5.3 相机节点 / 玩家节点（不用猜，有硬不变量）

- **相机节点**：包围盒三边都是 `200000` 的"无限盒"，且位置与相机矩阵的 position **完全重合**（实测距离 0.0）。
  用它可以当锚点。
- **玩家节点**：离相机节点 **约 45 单位**（实测：前 21.5 / 右 3.0 / 上 −39.4），
  人形三围（高 14~23、宽 5~22、深 5~18 单位）。同一个进程里只有它满足这一条。
- 走一步差分可以验证：相机节点位移与相机矩阵位移完全一致，玩家节点位移也一致。

### 5.4 单位与手感

| 项目 | 实测值 |
|---|---|
| 长度单位 | 1 单位 = 0.1 米 |
| 鼠标灵敏度 | 3.7 像素 / 度（+dx 向右转，+dy **向下**看） |
| 相机在玩家身后 | 水平约 2.2 米 |
| 单人步行速度 | 约 1.5 米/秒（按死 W） |

### 5.5 读内存的正确姿势

```js
// ✅ 必须用 execFileSync 拿 buffer
execFileSync(ADB, ['-s', DEV, 'exec-out',
  `dd if=/proc/${pid}/mem bs=65536 skip=${Math.floor(addr/65536)} count=1`],
  { maxBuffer: 240*1024*1024, encoding: 'buffer' });

// ❌ 用 cmd.exe 重定向到文件会静默失败（退出码 1，文件不生成）
```

单块 64 KB 读取约 50~60 ms；整区 44.5 MB 约 1.1 s。
**单次转储不要超过约 45 MB**（多个大区域一起读会把宿主机内存打爆，模拟器会崩）。

### 5.6 输入层

**C# 编译的 exe 里调 `keybd_event` 进不去游戏；PowerShell 里调同样的 API 可以。**
所以输入层是一个**常驻 PowerShell 进程**（`input_helper.ps1`），用 stdin 行协议驱动：

```
HWND <hex>    REFRESH    FOCUS    KD <vkhex>    KU <vkhex>    TAP <vkhex>
M <dx> <dy>   CLICK      SLEEP <ms>    QUIT
```

## 六、已知限制（这些是真结论，不是没做完）

1. **不能按"外形"认资源。** 8 块石头记下来的包围盒，8 个全都不一样：
   `47.94/24.54/36.38`、`45.66/38.78/33.64`、`46.56/27.05/50.15`、`38.35/26.50/30.52`、
   `54.61/22.28/47.94`、`54.15/39.68/42.32`、`51.06/40.35/38.11`、`60.48/44.04/50.88`。
   连"旋转不变量"（水平两边平方和）都不守恒（3621 / 3217 / 4683 / 2402 / 5280 / 4691 …）。
   **所以每块石头是各自的模型，只能按坐标记。**
2. **id 不能当身份。** 同一个点 `(2077.09, 416.36, -4676.12)` 一晚上 id 变过
   `0x7fd4 → 0x5b87 → 0x335c → 0xf25d → 0xece`。池槽复用 / 换 LOD 都会重编号。**只存坐标。**
3. **采空不会反映在节点上。** 挖掉的石头节点仍然留在内存里，包围盒也不变（Δ=0.00）。
   所以"节点还在"不能判失败，脚本不判断采没采到，打完就走。
4. **包围盒会膨胀。** 近距离/高亮时同一块石头的包围盒会从 `36.13→47.94→56.75` 变化，
   导致"点到盒距离"算成 0（日志里那一串"（在盒子里）"就是这个）。**站位判据应该改成用射线命中距离。**
5. **树不在这个节点表里。** 白名单里 4 个"tree"点，人站上去 3 米内一个节点都没有；
   多次全图扫描也没找到树木量级的节点。树应该是实例化植被，不是独立场景节点。
6. **射线命中距离的物理下限约 4.0~4.6 米。** 相机在玩家身后 2.2 米，石头宽 5.1~5.4 米、高 4.0 米，
   人贴脸站时射线打到石头近面就是 4.0~4.1 米。把门禁设成 2 米永远不可能通过。
7. **白名单坐标不代表"现在还有资源"。** 采过的点在刷新冷却内查不到节点，会跳过（不空挥）。

## 九、故障排查

| 现象 | 原因 / 处理 |
|---|---|
| `★ pid 变了` | 游戏重启过，重新跑 `node camfind6.js` |
| `读相机失败` | `session.json` 过期，同上 |
| `没有 session.json` | 第 0 步没做 |
| `adb devices` 显示 `offline` | `adb kill-server` → `adb start-server`，等 10 秒 |
| `/proc/<pid>/maps` Permission denied | `adb root` 没开（模拟器重启会丢） |
| 键按了没反应 | 游戏窗口没焦点；或输入助手进程残留（`Get-Process powershell` 清掉） |
| 人物原地转圈 | 视角误差没收敛（鼠标被手动抢了），停手别动即可 |
| 走到一半放弃 | 连续 4 次脱困无效，说明真被挡死；检查目标是否在墙/水里 |
| 宿主机卡死 / 模拟器崩 | 单次转储太大，控制在 45 MB 以内 |
